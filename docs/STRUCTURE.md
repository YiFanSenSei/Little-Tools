# 工具隔离约定

1. 每个工具位于 `tools/<slug>/`。不要把工具源码、配置或运行数据放进仓库根目录。
2. 每个工具有自己的 README、依赖声明、测试、`.env.example` 和 `data/`。无需共享 Node/Python 环境；根目录只提供导航，不安装全仓库依赖。
3. 不读取根目录或兄弟工具的 `.env`，不写入其他工具目录。自定义数据路径需要用户显式配置，默认是本工具的 `data/`。
4. 在 `tools.json` 登记唯一 id、目录、命令及未使用的默认端口。注册表和审计脚本会检查默认端口冲突；用户自行覆盖端口后仍应保证唯一。
5. 系统任务名称必须带工具前缀及安装目录哈希。只安装/卸载本工具的任务，不结束其他工具的进程。当前拾星使用 `GitHubRadar-Weekly-<目录哈希>`。
6. CI 位于根目录 `.github/workflows/<工具名>.yml`，测试在对应工具目录执行。工具内部的 `.github` 模板仅用于独立导出，不会作为仓库工作流执行。
7. 每个工具维护 `release-files.json` 源码白名单。新增根目录公共文件还要更新 `repository-files.json`，禁止把运行目录整体压缩上传。
8. 公共代码确需复用时再引入清晰的公共模块，不通过跨目录相对路径偷偷依赖另一个工具。

## 新增步骤

- 新建工具目录及 README，明确运行环境、入口、端口、数据和停止方式。
- 准备源码白名单和脱敏配置示例，在 `tools.json` 注册工具。
- 在首页工具表添加链接，添加该工具的 CI；非 Node 工具需自行定义对应的独立运行和测试方式。
- 运行当前工具测试、仓库 `npm run privacy:check`，确认没有端口冲突、个人配置或未审核文件。
- 仓库通用审计当前使用拾星的规则扫描器；若未来移除拾星，先将该扫描器提取为公共模块。它不要求未来工具使用 Node 作为自身运行环境。

## 从单工具版本迁移

旧目录的运行数据不会随源码上传。若要保留自己的记录，可在本机手动复制旧 `data/` 到新工具目录的 `data/`，不要提交这些文件。

移动目录后先从原目录卸载 Windows 计划任务，再在新目录安装；旧目录里的服务不会因为克隆仓库自动停止。为避免本地端口占用，请先关闭旧应用。未迁移之前继续使用旧安装也可以，它的数据和任务保持独立。
