# 发布前检查

```sh
npm test
npm run privacy:check
npm run release
```

`release/` 下每次生成一个新目录，包含：

- `github-radar/`：按 `release-files.json` 白名单复制的干净源码，可用它初始化仓库并上传。
- `github-radar-<版本>.zip`：同一份源码，包含隐藏的 Git 配置和 CI 文件。
- `SHA256SUMS`：ZIP 的 SHA-256 校验值。

不要把整个工作目录直接压缩上传。发布包没有 `.git`、`.env`、运行数据、日志和个人使用截图。`.env.example` 只包含空 token 与通用配置。新加的文件默认不会进入发布包。

检查器会检查白名单源码中的常见 token、私钥和个人路径模式；如果当前目录已有 Git 仓库，还会拦截已跟踪的私密文件及未经白名单审核的文件。它不打印命中的秘密值，也不能保证发现所有个人信息。

## Git 身份与历史

Git 提交本身带有作者姓名和邮箱，`.gitignore` 不会隐藏这些信息。上传前在**准备发布的仓库目录**中检查：

```sh
git config --get user.name
git config --get user.email
git log --format=fuller
git status --short
git diff --cached
```

需要隐藏邮箱时，在 GitHub 账号的 Emails 设置中启用邮箱隐私，使用 GitHub 给你分配的 noreply 地址；作者名也会公开，可使用你选择的公开昵称。仅在发布仓库内设置，不必修改全局配置。本项目不会自动设置、输出或上传你的 Git 身份。

已经提交到 Git 历史的秘密不会因为添加 `.gitignore` 而消失。若曾泄漏凭据，先撤销/轮换；清理历史后再上传。没有需要保留的公开历史时，可以从干净源码目录初始化新仓库，避免带入本机历史。请先自行确认要保留哪些提交。

## 人工复核

- 检查源码、文档中的姓名、邮箱、账号、机器名、目录、私有网址及你的业务数据。
- 不要直接使用本机截图；使用合成数据重拍后再单独审核。
- Windows 计划任务记录和本地配置仅保存在被忽略的 `data/`，不属于源码。
- GitHub 仓库拥有者账号、公开提交作者名无法通过源码打包隐藏。
- 新仓库先检查文件列表与提交信息，再推送；本工具不会执行 push 或上传。

## 后续可优化

1. 可配置的运行时间与时区，及 macOS/Linux 的系统调度安装助手（目前可手动配 cron）。
2. 基于上次报告显示「新上榜」「排名变化」，收藏/屏蔽项目。
3. 元数据缓存、条件请求与更清楚的网络诊断，减少重复 API 请求。
4. README 摘要与可选模型评审；需要单独设计密钥保护、费用与仓库内容的提示注入隔离。
5. 自动清理旧报告、任务安装状态实时检测，及真实 HTML 改版监测。
